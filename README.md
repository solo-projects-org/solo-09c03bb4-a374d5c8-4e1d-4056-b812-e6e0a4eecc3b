# 工业炉保温验收 · 温度格网交接页

用 Flask + SQLite 实现的炉衬测温方阵四叉树分区与供数交接工具。

## 它做什么

1. **上传测温方阵 CSV**：行列数相等且边长为 2 的幂（2、4、…、512）；
   格内填整数摄氏度，空白表示未测；UTF-8/GBK 编码、可选表头。
2. 填入**允许温差**后，从整张网格逐级四等分，用**最少的互不重叠方块**
   覆盖全部实测格：
   - 方块内不得含未测格；
   - 每块报最高温，块内任一读数与最高温之差不超过允许温差
     （整数温度下等价于 `max - min <= tol`）。
3. 网页按 1 基行列号**成批补测或清空**矩形区域，只重新核算包含改动格的
   四叉树节点与覆盖块。
4. **下载现行供数 CSV**：块的位置、边长、温度来自同一批已生效数据；
   补测或写入失败时整笔事务回滚，旧表仍可下载。
5. **档案复原**（炉壁复验找回旧测温表）：导入本工具下载的非空供数 CSV
   建档，再上传纸档补证（行、列从 1 开始的整数温度），随时流式下载
   复原 CSV；与现行格网完全独立。
6. 全程用 Docker Compose 启动。

## 为什么块数最少

合法性可“遗传”：一个方块合法（无未测格且温差不超限），其任意子方块也合法。
因此最优覆盖就是所有**最大合法节点**——自身合法、父节点不合法的四叉树节点。
任何不重叠方块覆盖都无法跨越四叉树对齐边界，所以每个最大合法节点至少需要
一块，本方案每节点恰用一块，块数最少。`tests/` 中有小网格暴力枚举对照。

## 数据与增量核算

SQLite 表（见 `app/db.py` 建表语句）：

| 表 | 作用 |
|---|---|
| `grid` | 方阵边长与当前允许温差 |
| `cells` | 每格温度，`NULL` 表示未测 |
| `nodes` | 四叉树内部节点（size≥2）的计数、温区与合法标志 |
| `batch` | 批次，每次成功的上传/改温差/补测清空各产生一批，`is_current=1` 为现行 |
| `block_op` | 块变更日志：`base` 整套、`add` 新增、`tombstone` 作废，保留批次历史 |
| `blocks_current` | 现行块物化表，与 `block_op` 同事务维护，下载直接顺序读 |
| `event_log` | 操作审计 |
| `archive` | 复原档案（全表至多一行，整档替换；id 单调递增作页面令牌） |
| `archive_block` | 档案内的供数块（来自本工具下载的供数 CSV） |
| `evidence` | 纸档补证，一格一行，冗余记录所属块坐标 |

补测/清空的增量步骤（`db.apply_edits`）：

1. 取改动格的全部祖先节点（单格只有 log₂N 个）；
2. 自底向上只重算这些节点的统计与合法标志；
3. 自根向下收集块增量：未受影响子树整棵跳过，受影响路径按新合法性
   写 `add` / `tombstone`；块合并时用区域墓碑作废被吸收的旧块，
   块拆分时按新结构补发存活子块；
4. 全部在一个 `BEGIN IMMEDIATE` 事务内，异常回滚，旧批次与旧供数不变。

下载与页面读同一张 `blocks_current`，保证位置、边长、温度同源。

## 档案复原（`app/archive.py`，独立于现行格网）

电子档只剩供数块、纸档还能补出部分原值时，在「档案复原」页：

1. **导入供数 CSV 建档**：只接受本工具下载的非空供数 CSV；校验四叉树
   对齐、块间不重叠、温度区间合法、覆盖格数与边长相符。网页只保留一份
   档案——新档生效即整档替换旧档及其补证，且页面以下发的档案号作令牌，
   **旧页面上的补证无法再写入新档**；校验或写入失败时旧档案原样保留。
2. **上传纸档补证 CSV**：每行 `行,列,温度`（1 基，整数，首行可为表头）。
   入库前逐格校验：坐标须落在某供数块内、温度不得超出该块所报范围；
   同格同值重传幂等跳过；**同格异值**，或合并后某块**无法实际达到所报
   最高/最低温**（不存在与证据一致的联合赋值），则整份补证退回、
   分毫不写。
3. **下载复原 CSV**：逐行输出全部格子的 `行,列,温度,状态`，四态——
   `纸档原值`（补证直接给出）、`唯一能推回`（块区间退化为单值，或块内
   仅剩一格未补证且所报最高/最低温只能由它承担）、`已测但原值不明`
   （温度留空）、`未测`（温度留空）。下载流式生成，不铺开整张方阵；
   读事务快照保证文件只含**下载开始时**已入库的档案与读数，下载期间
   仍可补证；换档或补证失败不影响此前结果，重启后按已收证据重新下载
   亦一致。

## 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据存于命名卷 `furnace-data`（容器内 `/data/furnace.db`），重建容器不丢数。

## 本地开发与自测（不依赖 Docker）

环境无 pip 时可先把依赖装到项目本地目录：

```bash
python3 -m ensurepip            # 若系统提供
python3 -m pip install --target .pylibs -r requirements.txt
PYTHONPATH=.pylibs:. python3 -m unittest tests.test_app -v
PYTHONPATH=.pylibs:. FURNACE_DB=/tmp/f.db python3 -m flask --app app.wsgi run --port 8000
```

## 自测覆盖（`tests/test_app.py` 24 个用例 + `tests/test_archive.py` 24 个用例）

- CSV 解析：空白未测、非 2 次幂/缺列/非整数/超温拒绝、显式表头；
- 四叉树：均匀网格一块、未测格不被覆盖、温差迫使分裂、随机网格的
  不重叠/铺满/温差约束、小网格暴力枚举验证块数最少；
- 服务层：120 轮强随机补测/清空 + 多次改温差下，**物化现行块、delta 日志
  还原、纯算法全量重建三者逐块一致**；多种边长（含 1、2 退化情形）；
- 增量性：单格编辑只重算 log₂N 个祖先节点；
- 事务：越界/失败回滚后旧批次仍可下载；批次历史与现行标志唯一；
- Web 端到端：上传、批量补测、清空、改温差、下载、坏输入与坏 CSV 不污染旧表；
- 档案复原：供数 CSV 空档/缺列/未对齐/重叠/越界/区间非法拒绝；补证
  落块与区间校验、同格同值幂等、**同格异值与无法达到所报极值整份退回
  且分毫不写**；旧页令牌写入新档被拒；复原 CSV 四态与留空规则、
  唯一推回值与真值随机对照；**下载读事务期间补证照常提交而本文件仍是
  开始时快照**；重启后按已收证据复现；复原全程不改现行格网。

## 已知边界与取舍

- 边长上限 512、温度合理区间 `[-100, 3000] ℃`，在 `app/csvutil.py` 可调。
- 大网格（512）全量上传约 3–4 秒、20 万块下载约 1 秒（流式输出，内存恒定）；
  单格/小批量增量编辑为毫秒级。
- 复原 CSV 下载同样流式：512×512 全量约 0.3 秒，内存峰值与方阵大小无关。
- 改允许温差是全局重算，会以整套 `base` 块重建并截断旧 delta 链；
  补测/清空才走局部增量，历史 delta 连续保留。
- 界面网格视图对大于 32 行/列的方阵只预览左上角，完整数据以批量操作和
  下载 CSV 为准。
- 档案复原先入为主：补证一旦收录不可改不可删（同格异值只会整份退回），
  纠错只能靠导入新供数 CSV 整档重建后重新补证。
